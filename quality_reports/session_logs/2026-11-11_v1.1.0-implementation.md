## v1.1.1 Patch: Orthogonal Classification Fix (2026-11-12)

**Root cause:** `participation_class` was derived from slashing sign (`slashed_tokens ≤ 0` → WRONG_VOTE/DID_NOT_VOTE). Zero-token voters who voted correctly in the resolution round were misclassified as WRONG_VOTE (2,345 rows) or DID_NOT_VOTE (96,326 rows).

**Discovery path:**
1. User identified 442 edge cases: 115 disagree-only + 327 wrong-only
2. Investigation showed all 327 wrong-only cases had `slashed_tokens == 0`, voted the correct price
3. User's contract review confirmed VotingV2 uses `lastVotingRound` only — prior-round hypothesis was wrong
4. Zero reward = no penalty pool to redistribute (unanimous correct vote) or tiny stake rounding

**Fix (round 1):** Separated behavioral and economic classification into orthogonal columns:
- `participation_class`: CORRECT_VOTE / WRONG_VOTE / DID_NOT_VOTE / UNKNOWN — derived by comparing revealed price to resolved price in resolution round
- `reward_class`: POSITIVE_REWARD / NEGATIVE_SLASH / ZERO_CHANGE — from slashing sign only
- Dropped `incentive_type` (REWARD/PENALTY — strict coarsening of sign, no additional contract info)

**Fix (round 2, user corrections):** Added NOT_OBSERVED reward_class + ballot-only rows:
- DID_NOT_VOTE eligibility: confirmed by VoterSlashed record (voter was staked)
- NOT_OBSERVED: 40,750 resolution-round ballot voters with no VoterSlashed event (lazy `updateTrackers`)
- NaN for slashed_tokens_raw, request_index, block_number, tx_hash, log_index on NOT_OBSERVED rows
- 4-row edge case regression test: CORRECT_VOTE+ZERO_CHANGE, WRONG_VOTE+ZERO_CHANGE, WRONG_VOTE+NOT_OBSERVED, DID_NOT_VOTE+ZERO_CHANGE
- Protected price comparison against NaN resolved_price (can_compare guard)

**v1.1.0 → v1.1.1 transition matrix (VoterSlashed rows):**
- 1,920,685 CORRECT_VOTE → CORRECT_VOTE (unchanged)
- 972,446 DID_NOT_VOTE → DID_NOT_VOTE (unchanged)
- 63,238 WRONG_VOTE → WRONG_VOTE (unchanged)
- 2,016 WRONG_VOTE → CORRECT_VOTE (zero-token correct voters — the main bug)
- 2,531 WRONG_VOTE → DID_NOT_VOTE (non-resolution-round reveal)
- 40,750 new NOT_OBSERVED rows (ballot-only, previously not in table)

**Impact on edge cases:**
- 327 wrong-only → 0 (resolved: zero-token correct voters now CORRECT_VOTE)
- 115 disagree-only: ballot coverage gap fixed (40,750 ballot-only voters now in table as
  NOT_OBSERVED), but economic penalty observation remains pending — slashing events for

## Check A: Request Linkage Audit (30 Cases)

**Date:** 2026-11-12
**Finding:** Same-request temporal disagreement, NOT cross-request.

Recovered adapter's `requestTimestamp` from `QuestionInitialized` events on Polygon
for all 30 previously audited cases.

**Key discovery:** Polymarket adapters emit a DIFFERENT `QuestionInitialized` event
than the generic UMA adapter. Signature:
`QuestionInitialized(bytes32 indexed, uint256 indexed, address indexed, bytes, address, uint256, uint256)`
topic0 = `0xeee0897a...` (not `0x9501bedc...`). The `requestTimestamp` is in topic[2].

**Results:**
- 27/30 (90%): adapter requestTimestamp == DVM requestTimestamp (SAME request)
