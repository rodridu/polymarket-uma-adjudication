# Session: v1.1.0 Implementation

**Date:** 2026-11-11
**Goal:** Implement commit/reveal/slashing layer (Layer 3) for v1.1.0

## Plan Summary

Add three new release tables (commits, participation, voter_request_incentives) via two new pipeline scripts (04b, 04c) plus modifications to 06/07/tests/docs.

## Key Decisions

- VoterSlashed uses receipt-based approach (459 tx receipts, not 4,261 per-request log queries) because it lacks identifier topic
- participation_class uses request-level reveal status, not resolution-round-specific (documented limitation)
- DID_NOT_VOTE covers both "committed but didn't reveal" and "never committed" — matches UMA protocol semantics; participation table provides the finer granularity
- rounds.parquet expanded to include commit-only rounds (not just ballot rounds)
- C12 and C16 adjusted for edge cases (commit-only rounds, NO_REVEALS requests)

## Critical Bugs Found and Fixed

2. **07 C12 commit-only rounds** — participation.round_id checked against rounds built only from ballots. Commit-only rounds fail. Fixed by including commit rounds.
3. **06 empty frame .apply()** — on empty DataFrame returns DataFrame not Series. Fixed with list comprehension.

### Round 2

6. **04c _bytes32_to_str outside try** — could stall on non-UTF-8. Moved inside try/except.
7. **04b/04c JSONL truncation** — crash mid-append leaves corrupt line. Fixed with error-tolerant parsing in `done` loader.

### Round 3

## 04c Rewrite: Receipt → Global Log Scan

**Root cause:** VoterSlashed events are emitted during `updateTrackers()` calls in subsequent rounds, NOT during `processResolvable()`. Receipt-based Phase 2 found only 1 event across 459 txs.

**Fix:** Rewrote Phase 2 to use global `eth_getLogs` scan for ALL VoterSlashed events from VotingV2, post-filtered by `requestIndex ∈ request_index_map`. Phase 1 (receipt-based request_index_map) kept — already complete (4,261 entries).

**Review round:** cavecrew-reviewer found 6 critical bugs in initial rewrite:
1. Silent empty on retry exhaustion → now raises
2. HTTP 400/413 retried as transient → now immediate split signal
3. Rate limit conflated with result limit → separate handling
4. Infinite loop at min chunk size → raises when can't shrink further
5. Matched logs lost on crash → now written per-chunk before checkpoint
6. requestIndex uniqueness not asserted → added (global monotonic in VotingV2)

## v1.1.1 Patch: Orthogonal Classification Fix (2026-11-12)

**Root cause:** `participation_class` was derived from slashing sign (`slashed_tokens ≤ 0` → WRONG_VOTE/DID_NOT_VOTE). Zero-token voters who voted correctly in the resolution round were misclassified as WRONG_VOTE (2,345 rows) or DID_NOT_VOTE (96,326 rows).

**Discovery path:**
1. User identified 442 edge cases: 115 disagree-only + 327 wrong-only
2. Investigation showed all 327 wrong-only cases had `slashed_tokens == 0`, voted the correct price
3. User's contract review confirmed VotingV2 uses `lastVotingRound` only — prior-round hypothesis was wrong
4. Zero reward = no penalty pool to redistribute (unanimous correct vote) or tiny stake rounding

**Fix (round 1):** Separated behavioral and economic classification into orthogonal columns:
- `participation_class`: CORRECT_VOTE / WRONG_VOTE / DID_NOT_VOTE / UNKNOWN — derived by comparing revealed price to resolved price in resolution round
- `reward_class`: POSITIVE_REWARD / NEGATIVE_SLASH / ZERO_CHANGE — from slashing sign only
- Dropped `incentive_type` (REWARD/PENALTY — strict coarsening of sign, no additional contract info)

**Fix (round 2, user corrections):** Added NOT_OBSERVED reward_class + ballot-only rows:
- DID_NOT_VOTE eligibility: confirmed by VoterSlashed record (voter was staked)
- NOT_OBSERVED: 40,750 resolution-round ballot voters with no VoterSlashed event (lazy `updateTrackers`)
- NaN for slashed_tokens_raw, request_index, block_number, tx_hash, log_index on NOT_OBSERVED rows
- 4-row edge case regression test: CORRECT_VOTE+ZERO_CHANGE, WRONG_VOTE+ZERO_CHANGE, WRONG_VOTE+NOT_OBSERVED, DID_NOT_VOTE+ZERO_CHANGE
- Protected price comparison against NaN resolved_price (can_compare guard)

**v1.1.0 → v1.1.1 transition matrix (VoterSlashed rows):**
- 1,920,685 CORRECT_VOTE → CORRECT_VOTE (unchanged)
- 972,446 DID_NOT_VOTE → DID_NOT_VOTE (unchanged)
- 63,238 WRONG_VOTE → WRONG_VOTE (unchanged)
- 2,016 WRONG_VOTE → CORRECT_VOTE (zero-token correct voters — the main bug)
- 2,531 WRONG_VOTE → DID_NOT_VOTE (non-resolution-round reveal)
- 40,750 new NOT_OBSERVED rows (ballot-only, previously not in table)

**Impact on edge cases:**
- 327 wrong-only → 0 (resolved: zero-token correct voters now CORRECT_VOTE)
- 115 disagree-only: ballot coverage gap fixed (40,750 ballot-only voters now in table as
  NOT_OBSERVED), but economic penalty observation remains pending — slashing events for
  these voters have not been triggered (lazy `updateTrackers`), so the original phenomenon
  (minority vote without observed WRONG_VOTE slashing) still exists for NOT_OBSERVED rows.
  9,983 NOT_OBSERVED rows are confirmed WRONG_VOTE by price comparison — systematic gap in
  slashing coverage for wrong voters when `updateTrackers` has not been called.
- C14 validation rewritten for orthogonal consistency checks
